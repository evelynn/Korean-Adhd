# 한국어 문체 규칙 (긴 글·윤문용)

문서, README, 보고서, 공지, 메일을 쓰거나 글을 다듬을 때, 영어를 한국어로 옮기거나 번역을 원문과 대조할 때 읽는다. A~J 규칙은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)(MIT, epoko77-ai) 커밋 `b37e020`의 `quick-rules.md`에서 가져왔고 패턴 번호도 같다. S1은 강한 신호, S2는 중간 신호다. "고칠지 판단하기", K~M, "장르별 기준", "결과 돌려주기"는 [K-Humanizer](https://github.com/evergreentree97/K-Humanizer)(MIT, K-Humanizer contributors) 커밋 `c24b2c5`의 `SKILL.md`·`patterns.md`·`evaluation.md`·`use-cases.md`를 한국어로 옮겨 정리했다.

**건드리지 않는 것.** 고유명사, 제품명, 수치, 날짜, 단위, 발화자가 있는 직접 인용, 법률 조문, 수학·화학·통계 표기, 업계 표준 약어(LLM, GPU, API 등)는 탐지와 윤문에서 모두 제외한다. 필자가 강조하려고 따옴표로 감싼 말은 필자의 문장이므로 고쳐도 된다.

**서법 보존.** "~해야 한다"를 "~한다"로, "~일 수 있다"를 단정으로 바꾸지 않는다. 표지가 너무 반복되면 서법은 그대로 두고 배치만 바꾼다.

**내용 앵커.** 고치기 전에 문장별 핵심 명사와 개념어를 추린다. 조사와 어미는 바꿔도 되지만 그 어휘는 결과에 한 번 이상 남긴다. 확신이 없으면 그 문장을 원래대로 둔다.

**과윤문 방지.** AI 특유의 표현을 지운 분량을 제외하고 고친 분량이 30%를 넘으면 고친 곳을 줄인다. 50%를 넘으면 처음부터 다시 한다.

**고칠지 판단하기.**
- 금지어는 없다. 아래 패턴은 어색한 원인을 찾는 단서다. 패턴에 걸려도 그 자리에서 자연스러우면 둔다. "통해", "제공", "진행", "관련하여"도 맞는 자리에서는 평범한 한국어다("홈페이지를 통해 안내드립니다", "배송 지연 관련 안내").
- 고칠 때는 이유를 하나 댈 수 있어야 한다. 뜻·사실 오류, 문법 오류, 독자가 알아챌 번역투, 장르나 격식 불일치가 이유다. 동의어로 바꾸기, 조사 하나 덜기, 고친 티 내기는 이유가 아니다.
- 맞는 격식어를 짧은 구어로 바꾸지 않는다. "품질 관리에 중점을 두었습니다"와 "품질 관리에 집중했습니다"는 뜻이 다르다.
- 요청받은 부분만 고친다. 앞뒤 글은 맥락으로만 읽는다. 구조 바꾸기, 내용 고르기, 새 문단 쓰기는 요청이 있을 때만 한다.
- 이미 자연스러운 글은 그대로 돌려준다.

## A. 번역투 (Translation-ese) — S1~S2

- **A-1** [S1] "~에 대해(서)" **한 문단 3회+ 밀집**(사람이 3배 더 쓰는 표현 — 기본 보존) → 목적격 조사로 직결("X에 대해 논의" → "X를 논의")
- **A-3** [S1] "~에 있어(서)" → "~에서" 또는 "~을 볼 때"
- **A-5** [S2] "~와 관련하여/관련된" → "~에", "~의"
- **A-6** [S2] "~에 기반하여/바탕으로" 남발 → "~로", "~을 보고"
- **A-7** [S1] "가지고 있다", have/make/take/give+명사 직역 → 형용사-동사 환원 또는 이중주어("강한 경쟁력을 가지고 있다" → "경쟁력이 강하다")
- **A-8** [S1] 이중 피동 "~되어진다/~지게 된다" → 능동 또는 단일 피동("판단되어진다" → "판단된다")
- **A-9** [S2] "~에 의해" 피동 → 행위자를 주어로("AI에 의해 생성" → "AI가 만든")
- **A-10** [S2] 같은 "~할 수 있다"가 4회+ 반복 (**의학·법률·정책 텍스트는 미적용 — 헤지가 의미다**) → **단정 전환 금지**. 일부만 다른 완곡 표현("~할 여지가 있다·~할 수도 있다")으로 분산해 리듬만 깬다. 의학·법률·정책이면 분산조차 하지 않고 원문 보존
- **A-11** [S2] 기본 보존 · "~을 위해" 목적절이 한 문단에 밀집할 때만(사람이 더 쓴다) → 밀집 문단에서만 "~려고", "~도록", "~위한"으로
- **A-15** [S2] 추상 주어 + 만능 동사(보여준다/제공한다/가져온다), 사역-인지 동사 직역 → 구체 주어로 환원, 사역은 "X 때문에/덕분에/로 인해" 부사절, 인지 동사(suggest/show/indicate)는 "~에 따르면 ~이다"
- **A-18** [S2] 명사 앞 3어절 이상 관형구/관계절 좌향 수식 → 문장 분리 또는 후치 동격절("X를 만났는데, 그 X는 ~")
- **A-19** [S2] 이중 조사 "~에서의/~에로의/~으로의/~에의/~으로부터의" → 절-구로 풀어쓰기, 단순 "~의"는 비대상
- **A-20** [S2] "~되고 있다/~지고 있다"가 한 문단 3회+ → 일부만 추세 단언("심해졌다")으로 — 고립 사용은 보존
- **A-21** [S2] "단순한 X를 넘어 Y" 범위 상승 (사람 글 실측 0건) → "X만이 아니라 Y다"로 풀거나 넘어-구 삭제
- **A-22** [S2] "~은/는 명확하다·분명하다"(부사 "분명히"·동사구 "명확히 하다" 제외) → 평가 술어를 걷고 명제를 단언으로. 확신 강도는 부사로 보존. 앞에서 논증한 결론이면 유지
- **A-24** [S2] "더 이상 ~ 않다/아니다" 문서 2회+ 또는 결말부 재정의 문장 → "더 이상"을 "이제"로 환원하거나 변화 동사로 편다. 부정 명제를 긍정 단언으로 올리지 마라. **윤문 중 "더 이상 A가 아니라 B"를 새로 만들지 마라**

## B. 영어 인용·용어 과다 — S2

- **B-1** [S2] 한글 + 괄호 영어 병기 매번 반복("~(Sovereign AI)" 식) → 첫 등장만 병기, 이후 한글만
- **B-2** [S2] 설명 없이 낀 광고성 buzzword(seamless·robust·leverage 등) → 광고성만 한국어로 풀고 표준 technical term(API·prompt·token 등)은 원어 보존, 기계적 직역 금지

## C. 구조적 AI 패턴 (서식·레이아웃) — S1~S2

- **C-2** [S2] 칼럼-리포트에서 3개 이상 연속 불릿 블록 → 문단 산문으로 통합, 나열이 의미 있는 지점만 유지
- **C-5** [S1] 이모지 남발(리스트 머리, 헤딩, 강조) → 칼럼-리포트 장르면 전부 삭제
- **C-7** [S2] 문단 문두 "먼저-반면-결국" 3단 공식 → 접속사 1~2개로 줄이거나 본문에 녹여 제거
- **C-8** [S1] "A인가, B인가"·"A가 아니라 B"·"~것이 아니라"·"~것은 아니다" 대구 **2회+** 반복 → 한 번만 살리고 나머지는 비대칭 평서문·직접 단언으로. 전멸 금지. 사람 필자도 다용하는 수사이므로(532편 중 31편 실측) 연쇄로 몰려 있지 않으면 보존 우선
- **C-9** [S2] 숫자 괄호 인덱싱 "1) 2) 3)" 나열 → 본문에 녹이거나 "우선~", "다음으로~"로 어휘 변주
- **C-10** [S2] 콜론 부제 헤딩 "X: Y" 반복 → 헤딩을 단일 명사구로 압축, 단 학술-보고서의 실제 절 제목은 보존
- **C-11** [S1] 연결어미(-고/-며/-지만/-면서/-아서/-어서) 직후 쉼표 → 쉼표 제거, 6회+ = 강한 신호(KatFish 4.84배 분리도). **윤문이 새 연결어미 쉼표를 만들지 말 것 — 윤문 후 개수가 원문보다 늘면 실패**

## D. AI 특유의 표현 (Signature Phrases) — S1

- **D-1** 결산 lexicon "결론적으로/따라서/이를 통해/그러므로/요약하면/정리하자면" → 3회 초과 시 1~2건만 남기고 삭제-치환
- **D-2** "시사하는 바가 크다/주목할 만하다/매우 중요하다" 류 의의 과장 → 삭제 또는 구체 결론으로
- **D-3** 열거 도입 "크게 세 가지로 나눌 수 있다/다음과 같은" → 도입구 삭제하고 바로 본론 서술로
- **D-5** [S2] 의인화 추상 주어("기술이 묻는다", "시대가 부른다") → 사람-기관 주어로 교체 또는 의인화 동사 약화
- **D-6** [S2] 결말 공식 "~할 때입니다/~시점입니다/~할 순간입니다" → 구체 동사 단언으로, 문서당 1회 이하
- **D-7** [S2] 변환 공식 "X에서 Y로/X을 넘어 Y로" 반복 → 직접 단언으로, 문서당 1회 이하
- **D-8** [S2] 분열문 "필요한/중요한 것은 ~이다" + 명사 변종 "문제는/핵심은/관건은/답은 ~다·~는 점이다·~데 있다" → 주어-서술 직결로("필요한 것은 방향이다" → "방향이 필요하다" / "논쟁의 핵심은 생산성이다" → "논쟁은 생산성을 둘러싼 것이다")
- **D-9** [S2] "(으)로 이어진다"·"~에 직결된다" 결산 + 논리 결산용 "결국" 문서 2회+ → 인과 경로를 구체로 쓰거나 단문 단언으로. "결국"은 1회만 남긴다. **결말을 다듬으며 "결국·이유다"를 새로 만들지 마라(주입 금지)**
- **D-10** [S2] 문장 말미 "~하는 이유다" 도치 결산 → 순방향 단언("그래서 ~다")으로, 문서당 1회 이하. **결말을 다듬으며 이 도치를 새로 만들지 마라(주입 금지)**
- **D-11** [S2] 결말부(후반 30%) 문두 "향후/앞으로/중장기적으로" → 시간어 삭제 또는 원문에 있는 실제 시점·조건으로 교체(날조 금지)
- **D-12** [S2] 독립 문장 "과제도 남아 있다/한계도 분명하다/아쉬운 점도 있다" → 문패 삭제, 실제 과제를 첫 문장으로
- **D-13** [S2] 에세이 결말의 "어쩌면 ~일 것이다/비로소/천천히 ~이 됐다" → 성찰 부사를 빼고 구체 서술로(에세이 장르 한정)
- **D-14** [S2] 감각 술어 평가문("진단은 서늘하다/경고는 아프다") **1회+** · 사람 0건 사전 은유(잠식·청사진·적신호·경고등·신호탄·움켜쥐다·뿌리내리다·짓누르다) **1회+** · 그 외 개념 은유(청구서·과실·주춧돌 등) 문서 3회+ · **같은 은유 어근 3회+ 관통 반복(중심 은유여도 발동)** → 직역화 — 감각 술어는 관용구·구체 서술로("서늘하다"→"정곡을 찌른다"), 사전 은유는 명제로("잠식한다"→"점유율을 뺏는다"). 관통 은유는 가장 효과적인 1회만 남김("쥐다"→"가지다"). 명제 불명이면 보존, 주입 금지

## E. 리듬·문장 길이 균일성 — S2

- **E-1** 문장 길이 균일 + 100자+ 장문 부재 → 단문 1~2개 + 인접 문장을 이어 만든 장문 1개를 문단마다(내용 추가 금지)
- **E-2** 동일 종결어미 4문장+ 연속, 진행형 "~고 있다" 자동 매핑 → 종결어미 다양화, "~고 있다"는 단순 시제로 환원 가능 시 환원("읽고 있다" → "읽는다")
- **E-7** [S2 · estimated] 청자 경어법 단계(해라/하게/하오/해요/합쇼) 한 문서 내 혼재(대화-구어 한정) → 격식 등급 하나로 일관 유지

## F. 과도한 수식·중복 — S2

- **F-4** 한자어 명사화 -성/-적/-화 + 영어 명사화 -tion/-ment/-ness/-ity 직역 누적(문서 12회+) → 동사-형용사 어근으로 환원("the implementation of the policy" → "정책 시행")
- **F-5** [S2] "~적 N" 추상 체인("전략적 함의", "실천적 기반") 3회+ → 명사+명사 또는 풀어쓰기("전략 함의", "실천의 기반")
- **F-7** [S2] 범용 정책동사(확대·강화·개선·확보·마련·구축 등) 문서 밀집 + 추상 목적어의 "설계" → 구체 행위 동사로 해체(당위 표지 증폭 금지)

## G. 과도한 Hedging (완곡) — S2

- **G-1** 같은 추측 종결("~로 보인다/~로 판단된다/~라고 여겨진다")의 반복 → **단정 전환 금지**. 유보 강도는 유지한 채 종결 형태만 변주. 부정·이중부정이 낀 문장은 극성 확인 후 손대고 애매하면 원문 보존
- **G-2** 이중-삼중 완곡 "~할 가능성이 있을 수 있다/~로 보여질 수 있다" → 완곡 하나만 남김 — 남긴 완곡은 원문 극성·확신도 유지. 부정 낀 중첩과 협상·계약 문서, **의학·법률·정책 텍스트**는 접지 말고 원문 보존

## I. 형식명사·의존명사 과다 — S2

| 한국어만 | 윤문한다. 목소리와 구조를 지킨다 |
| 영어 원문 + 한국어 초안 | 원문과 어긋난 뜻부터 고치고 어색한 문장을 고친다. 정확하고 자연스러운 초안 문장은 둔다 |
| 영어만 | 한국어 어순으로 새로 짠다. 사실과 조건을 모두 지키면 문장을 합치고 나누고 순서를 바꿔도 된다. 단어 대응을 맞추지 않는다 |

- **K-1** 원문과 초안이 가격·날짜·한도·정책·약속에서 다르면 조용히 하나를 고르지 않는다. 사용자가 정본을 정했으면 다시 묻지 않고 따른다. 초안이 명백한 오역이면(빠진 예외, 약해진 "only") 고치고 한 줄로 알린다. 어느 쪽이 정본인지 모르고 상업 조건이 달라지면 질문 하나를 하거나 그 조항을 미해결로 표시한다. 원화 가격이나 부가세 표기만으로 한국어판이 승인됐다고 보지 않는다.
- **K-2** 영어에서 넘어온 대명사("당신", "그것", "그들", "우리는", 반복되는 "귀하의")는 누가 하는지 알 수 있을 때만 생략한다. 행위자가 바뀌면 다시 쓰거나 "고객님", "회원님", 브랜드명을 쓴다. 공문과 법률 고지의 "귀하"는 둔다.
- **K-3** 그대로 지킨다: 가격·통화·할인과 그 조건, 제품·요금제·브랜드·사람 이름, 수치와 비교·측정 조건, 계약·자격·사용 한도, 날짜·시각·시간대·마감, 환불·교환·배송·취소 정책, 보증 범위와 예외. 부정·예외·"최대"·"약"·"만", 확신 정도, 요청·제안·약속의 구분도 같다.
- **K-4** 원문에 없는 혜택, 성능 주장, 후기, 긴박감, 희소성, 사과, 약속, 판매 문구를 넣지 않는다. 통화·시간대·단위 변환과 현지 법률 용어 대체는 사용자가 근거와 함께 요청할 때만 한다. 날짜와 금액을 한국식 표기로 쓰는 것은 괜찮다. 원문에 없는 값은 `[보증 기간]` 같은 자리표시로 남긴다. 예시와 대안 문구에도 같은 제한을 둔다.
- **K-5** UI·알림 문자열은 자리표시자, 변수, 키, 마크업을 그대로 두고 새로 만들지 않는다. `{name}과`처럼 값의 받침에 따라 바뀌는 조사는 틀릴 수 있으므로 문장 구조를 바꾼다. 버튼은 하는 동작을 쓰고("구매하기") 영구 삭제나 결제 같은 실제 결과는 본문에 남긴다. 라벨을 설명문이나 광고 문구로 늘리지 않는다.
- **K-6** 단서가 없을 때 격식 기본값: B2B 메일·계약·공지는 합쇼체, 소비자 앱 문장은 해요체, 버튼·제목·배너·사양표는 명사구. 기존 한국어 문자열이나 브랜드 예시가 있으면 그것을 따른다. 이미 일관된 한국어를 기본값 때문에 바꾸지 않는다.
- **K-7** 번역식 명령형 행동 유도("지금 구매하세요!", "시작하세요")는 버튼이면 "구매하기", "무료로 시작하기", 본문이면 "~해 보세요"나 평서문으로 쓴다. 원문에 있는 마감과 긴박감은 남기고 없는 것은 넣지 않는다.
- **K-8** 한국어를 영어로 옮기는 일은 별개다. 충실하게 옮기고 이 문서의 한국어 문체 규칙을 영어에 적용하지 않는다.

## L. 읽는 사람 기준 — S2

- **L-1** 사람이 하는 일에 붙은 "~이 가능합니다/불가합니다" → "~할 수 있습니다/없습니다". 표와 라벨의 "당일 배송 불가"는 둔다.
- **L-2** 한 번에 끝나는 일에 붙은 "진행"("설치를 진행해 주세요") → "설치해 주세요". 여러 단계 과정과 진행 상태("환불이 진행 중입니다")는 둔다.
- **L-3** "~하도록 하겠습니다" → 말하는 사람이 직접 하는 확정 약속이면 "~하겠습니다". 다른 사람이 하게 하거나 노력만 약속하는 뜻이면 둔다. 약속의 강도를 바꾸지 않는다.
- **L-4** 이중 부정 "~가 아닌 한 ~할 수 없습니다" → "~인 경우에만 ~할 수 있습니다". 승인된 법률 문구는 둔다.
- **L-5** 영어 표현 직역("연락을 취하다", "게임 체인저", "손끝에서") → 원문이 뒷받침하는 동작이나 효과로 쓴다. 그 분야 독자가 이미 쓰는 말이면 둔다.
- **L-6** 제목이 이미 말한 것을 되풀이하는 자기소개("이 화면은 ~하는 화면입니다") → 보이는 항목과 상태를 쓴다. 독자가 확인할 수 없는 "한눈에"도 같다. 실제로 한 화면에 다 보이면 둔다.
- **L-7** 대상과 방법이 없는 "꼼꼼히 확인했다", "직접 검토했다" → 무엇을 어떻게 확인했는지 쓴다. 원문에 없으면 지어내지 않는다.
- **L-8** 비교 대상이 없는 "어긋남", "문제가 있다" → 무엇과 무엇이 달랐는지 쓴다. 확인만 했으면 확인한 사실만 쓰고 문제를 찾은 것처럼 쓰지 않는다.
- **L-9** 그 분야 사람이 아닌 독자에게만 내부 용어를 풀어 쓴다(컨텍스트 → 맥락·조건, 케이스 → 경우, 이슈 → 문제, 플로우 → 흐름·절차, 리스크 → 위험, 게이트 → 통과 조건, 회귀 → 기존 기능 동작 변경). 추상어를 다른 추상어로 바꾸지 않는다. "품질 게이트를 고도화했다"를 "품질 기준을 고도화했다"로 바꿔도 막연하다. 실제 규칙이나 점검을 쓴다. 고객이 쓰는 외래어(포인트, 쿠폰, 리뷰, 구독)와 제품이 이미 쓰는 용어는 둔다.

## M. 연결 관계 — S1

줄이기 전에 문단으로 읽는다. 다음 문장이 앞 문장을 보충하는지, 대비하는지, 설명하는지 확인한다.

| 원문이 뒷받침하는 관계 | 쓸 수 있는 연결 | 경계 |
| --- | --- | --- |
| 이유 → 행동·결과 | 그래서·따라서·-아서/-어서 | 원문이 인과를 말할 때만 쓴다 |
| 대비, 뒤 문장이 앞을 제한 | 하지만·다만·-지만·-는데 | 강조하려고 대립을 만들지 않는다 |
| 순서 | 이후·그다음·-고 나서·-한 뒤 | 순서를 인과로 바꾸지 않는다 |
| 같은 주제 보충 | 또·-고·-면서·"이 기준은" 같은 지시어 | "-면서"는 동시에 일어나는 일에만 쓴다 |

- **M-1** 줄이면서 원인·대비·순서·지시를 잇는 말을 지우지 않는다. 짧아져도 독자가 관계를 다시 짜 맞춰야 하면 실패다.
- **M-2** 근거 없는 인과·대비·순서를 연결어로 새로 만들지 않는다. "어제 안내문을 고쳤습니다. 오늘 문의가 줄었습니다."에 "그래서"를 넣지 않는다.
- **M-3** 문장을 합치면 사실마다 상태·조건·시점이 따로 읽혀야 한다. "초안은 완성했지만 검토는 아직 끝나지 않았습니다"처럼 두 상태를 모두 남긴다. 현재 상태가 앞으로의 변화처럼 읽히면 나눈다.
- **M-4** 같은 접속사가 문두마다 이어지면 연결어미로 합치고 순서는 지킨다("자료를 확인했습니다. 그리고 표를 고쳤습니다. 그리고 보냈습니다." → "자료를 확인하고 표를 고친 뒤 보냈습니다."). 접속사를 다른 접속사로 돌려 막지 않는다.
- **M-5** 독립된 불릿, UI 라벨, 일부러 끊은 대화에는 연결어를 넣지 않는다. 이미 잘 이어진 글은 그대로 둔다.

## 장르별 기준

- **코드 리뷰.** 사람이 아니라 코드를 말한다. "개선의 여지" 대신 구체적인 제안을 쓴다. 정말 확실하지 않을 때만 완곡하게 쓴다. 고칠 일이 흐려질 만큼 누그러뜨리지 않는다.
- **메신저.** 짧게 쓰되 한 생각을 토막 내지 않는다. 말투는 매체가 아니라 관계에 맞춘다. 이모지, 속어, 친한 척을 넣지 않는다.
- **동료 메일.** 요청을 앞에 둔다. 인사와 맺음은 관계만큼만 쓴다. 겹친 사과와 의례 문구를 줄인다.
- **문서·보고서.** 같은 개념은 같은 용어로 쓴다. 전문 용어는 처음 나올 때 한 번만 풀이한다. 절 제목을 되풀이하는 요약 문단을 쓰지 않는다.
- **일상 글.** 관계, 감정, 유머, 친밀도를 지킨다. 원문보다 따뜻하거나 강한 감정을 넣지 않는다.

## 결과 돌려주기

- 붙여 넣을 글부터 쓴다. 앞에 아무것도 쓰지 않는다.
- 단순 윤문·번역과 이미 자연스러운 글은 글만 돌려준다. "수정할 부분이 없습니다" 같은 판정, 고친 목록, 수치를 지켰다는 확인을 붙이지 않는다.
- 원문과 뜻이 어긋난 곳을 고쳤으면 무엇이 달랐는지 한두 문장 쓴다. 빠진 조건, 새로 생긴 약속, 바로잡은 격식 같은 실제 차이만 쓴다.
- 빠진 사실은 자리표시나 미해결 표시로 글 안에 남기고 그 값을 묻는 질문을 사실 하나에 하나씩 쓴다.
- 설명과 질문은 요청한 언어로 쓴다. 요청 없이 다른 어투나 여러 판을 내놓지 않는다. 고친 이유는 사용자가 물을 때 설명한다.

## 다 쓴 뒤 점검

하나라도 어기면 그 문장을 되돌리고 다시 쓴다. 다시 쓰는 것은 한 번까지 한다.

1. 고유명사, 수치, 날짜, 인용, 내용 앵커가 그대로 있는가
2. AI 특유의 표현을 지운 분량을 제외하고 고친 분량이 30% 이하인가
3. 칼럼이 에세이로, 리포트가 블로그 글로 바뀌지 않았는가
4. 원문의 격식이 그대로인가. 평어로 낮추지도, "-했-"을 "-하였-"으로 높이지도 않았는가
5. S1 패턴이 남지 않았는가. 연결어미 뒤 쉼표(C-11)는 원문보다 늘어도 실패다
6. 원문에 없던 비유와 AI 특유의 표현을 새로 넣지 않았는가
7. 부정, 예외, 한정어, 확신 정도, 완료 상태, 요청과 약속의 구분이 원문과 같은가
8. 있던 원인·대비·순서 연결이 남았고 원문에 없는 인과를 새로 잇지 않았는가
9. 고친 곳마다 이유를 댈 수 있는가. 이유 없는 동의어 교체는 되돌린다
10. 번역이면 금액, 통화, 날짜, 시간대, 자리표시자, 키가 원문과 같은가
