# Korean-Adhd

**한국어** | [한국어 회사어투](README.company.md) | [English](README.en.md)

Claude Code의 한국어 답변을 바로 행동할 수 있는 모양으로 바꾸고 번역투와 AI 상투구를 없애는 플러그인입니다.

[i-have-adhd](https://github.com/ayghri/i-have-adhd)의 답변 규칙과 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 한국어 문체 규칙을 합쳤습니다.

- **회사어투 옵션**: 답변을 "DB 확인 후 수정 완료" 같은 보고체로 줄입니다. 업무 보고에 맞춰 상태를 구분하고 추측을 쓰지 않습니다. [자세히 보기](#회사어투-옵션)
- **원작 대비 개선점**: 답변 모양과 한국어 문장을 한 번에 잡고 두 규칙이 부딪힐 때의 기준을 정했습니다. [자세히 보기](#원작-대비-개선점)

## 설치

약 2분 걸립니다. Claude Code와 Node.js가 필요합니다. Node.js가 없으면 세션을 시작할 때마다 훅 오류가 기록되지만 세션은 계속됩니다.

1. Claude Code 세션 안에서 플러그인을 설치합니다.

   ```
   /plugin marketplace add evelynn/Korean-Adhd
   /plugin install korean-adhd@korean-adhd
   ```

2. 새 세션을 열고(`/exit` 후 `claude`) 규칙을 켭니다.

   ```
   /korean-adhd:korean-adhd
   ```

3. 아무 질문이나 합니다. 첫 줄이 할 일이고 끝 줄이 `다음:`으로 시작하면 켜졌습니다.

새 세션마다 자동으로 켜려면 터미널에서 플래그 파일을 만듭니다. 다음 새 세션부터 적용됩니다.

```bash
# macOS, Linux, Git Bash
touch ~/.claude/.korean-adhd-always
```

```powershell
# PowerShell
New-Item -ItemType File "$HOME\.claude\.korean-adhd-always"
```

i-have-adhd를 쓰고 있었다면 터미널에서 `claude plugin disable i-have-adhd@i-have-adhd`로 끕니다. 함께 켜도 Claude는 이 플러그인의 규칙을 따르지만 비슷한 규칙이 두 번 들어갑니다.

## 회사어투 옵션

답변을 회사 보고서의 보고체로 줄입니다. 채팅 답변과 업무 보고서에 적용되고 기본값은 꺼짐입니다. 규칙은 [`references/company-tone.md`](skills/korean-adhd/references/company-tone.md)에 있습니다.

켜는 방법은 두 가지입니다.

1. 지금 세션에서만 쓰려면 `/korean-adhd:korean-adhd`로 규칙을 켠 뒤 "회사어투 켜"라고 말합니다. 끌 때는 "회사어투 꺼"라고 말합니다.
2. 새 세션마다 쓰려면 플래그 파일을 만듭니다. `.korean-adhd-always` 파일이 함께 있어야 동작합니다.

   ```bash
   # macOS, Linux, Git Bash
   touch ~/.claude/.korean-adhd-company
   ```

   ```powershell
   # PowerShell
   New-Item -ItemType File "$HOME\.claude\.korean-adhd-company"
   ```

## 원작 대비 개선점

원작과 다르게 만든 점은 네 가지입니다.

1. **문장까지 바로잡습니다.** i-have-adhd는 답변 구조를 잡아 주지만 규칙 문서가 영어이고 한국어 문체 규칙이 없습니다. 여기에 한국어 문장 규칙을 더했습니다.
2. **쓰는 순간에 적용합니다.** im-not-ai는 다 쓴 글을 탐지하고 윤문합니다. 이 플러그인은 답변을 쓸 때 규칙을 적용하므로 별도 호출이 필요 없습니다.
3. **충돌 기준을 정했습니다.** i-have-adhd는 번호 목록을 요구하고 im-not-ai는 불릿 남용을 AI 티로 봅니다. 실행 단계와 선택지는 목록으로 쓰고 이유와 원리는 문장으로 잇도록 정했습니다.
4. **회사 보고체를 고를 수 있습니다.** 업무 보고에 맞는 어미와 상태 구분 규칙을 옵션으로 넣었습니다.

| 항목 | i-have-adhd | im-not-ai | Korean-Adhd |
| --- | --- | --- | --- |
| 주된 목적 | 답변 모양 | 이미 쓴 한글 글 윤문 | 답변 모양과 한국어 문장을 함께 |
| 적용 시점 | 켜 두면 매 답변 | 윤문을 요청할 때 | 켜 두면 매 답변, 긴 글은 상세 규칙 추가 |
| 규칙 문서 언어 | 영어 | 한국어 | 한국어 |
| 두 규칙의 충돌 처리 | 해당 없음 | 해당 없음 | `SKILL.md` 3장에 기준 명시 |
| 회사 보고체 | 없음 | 없음 | 옵션 제공 |

im-not-ai의 다단계 윤문 파이프라인과 Python 게이트는 넣지 않았습니다. 긴 글을 정밀하게 윤문하려면 im-not-ai를 직접 설치하는 편이 낫습니다.

## 앞으로 개선할 점

1. **답변 품질 평가 세트.** 지금 테스트는 답변이 규칙을 지키는지 검사하지 않습니다. `claude plugin eval`로 평가 세트를 만들 계획입니다.
2. **모델별 차이 측정.** 2026-11-03 실행에서 Sonnet은 회사어투와 `다음:` 줄을 지켰습니다. Haiku는 "한 줄로" 답하라는 요청에서 둘 다 지키지 않았습니다. 각 1회 결과라 표본을 늘려야 합니다.
3. **Node.js 없는 환경.** 항상 켜기 훅은 Node.js로만 동작합니다. 원작의 셸 구현 파일을 참고해 셸 훅을 함께 둘지 검토합니다.
4. **macOS와 Linux 시험.** 지금까지 Windows 11에서만 실행해 봤습니다.
5. **회사어투 단독 켜기.** 회사어투 파일은 항상 켜기 파일이 있어야 동작합니다. 회사어투 파일만으로 켜는 방식을 검토합니다.

## 적용 예시

아래 예시는 규칙을 설명하려고 직접 쓴 글입니다. 실제 답변은 모델과 대화 내용에 따라 달라집니다.

### 예시 1. 오류를 고칠 때

요청: 로그인하면 401이 나와. 어떻게 고쳐?

이전:

> 네, 확인해 보겠습니다. 인증 흐름에는 여러 요소가 있어서 먼저 구조를 살펴보면 미들웨어와 토큰 검증, 쿠키 처리가 관련되어 있습니다. 결론적으로 토큰 검증 부분을 수정해 볼 수 있을 것 같습니다. 참고로 의존성 버전도 낡았습니다. 도움이 되셨길 바랍니다!

이후:

> `src/auth.ts:42`의 `verifyToken`을 고치세요. 요청의 `Authorization` 헤더를 읽지 않습니다.
>
> 1. 42번째 줄에서 헤더를 읽도록 바꿉니다.
> 2. `npm test -- auth.spec.ts`를 실행합니다.
>
> 다음: 테스트가 실패하면 처음 실패한 줄을 붙여 주세요.

첫 줄이 할 일로 바뀌었습니다. 의존성 이야기는 지금 문제가 끝난 뒤 따로 묻습니다.

### 예시 2. 작업이 길어질 때

요청: API 문서 5개를 한국어로 옮겨 줘.

이전:

> 번역 작업을 진행하고 있습니다. 조금만 기다려 주시면 곧 완료될 예정입니다.

이후:

> 3/5단계 완료: 인증 문서를 옮겼습니다. 남은 시간은 약 5분입니다.
>
> 다음: 결제 문서를 옮깁니다.

어디까지 됐는지 매번 다시 말하고 시간은 숫자로 씁니다.

### 예시 3. 되돌리기 어려운 작업

요청: 오래된 브랜치 다 지워 줘.

이후:

> 지우기 전에 확인이 필요합니다. 대상은 12개이고 그중 `feature/payment`와 `fix/login`은 병합되지 않았습니다. 지우면 이 두 브랜치의 커밋을 찾기 어렵습니다.
>
> 다음: 병합된 10개만 지울지 12개 모두 지울지 알려 주세요.

삭제, 강제 push, 스키마 변경은 확인을 먼저 받습니다.

### 예시 4. 문장 바꾸기

## 들어 있는 규칙

전체 규칙은 [`skills/korean-adhd/SKILL.md`](skills/korean-adhd/SKILL.md)에 있습니다.

| 구분 | 내용 |
| --- | --- |
| 답변 모양 | 첫 줄은 행동, 단계에 번호, 끝 줄은 `다음:`, 곁가지는 뒤로, 현재 위치 다시 말하기, 시간은 숫자로, 목록은 5개까지 |
| 한국어 문장 | 번역투와 상투구 제거, 비유 제거, 연결어미 뒤 쉼표 제거, 강조용 굵은 글씨 제거, 말투 통일 |
| 그대로 두는 것 | 코드, 명령, 경로, 오류 원문, 수치, 날짜, 고유명사, 직접 인용, 불확실하다는 표현 |
| 규칙보다 우선하는 경우 | "설명해 줘" 요청, 되돌리기 어려운 작업, 세 번 연속 실패, 정말 모호한 요청, 규칙을 지키면 답이 없어지는 경우, 시스템 프롬프트와 하네스 규칙 |
| 긴 글과 윤문 | 문서, 메일, 보고서를 쓸 때 [`references/korean-rules.md`](skills/korean-adhd/references/korean-rules.md)를 읽음 |

사용자가 영어로 쓰면 영어로 답하고 답변 모양 규칙만 적용합니다.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| `/korean-adhd`가 동작하지 않습니다. | 전체 이름 `/korean-adhd:korean-adhd`로 입력합니다. |
| 새 세션에서 자동으로 켜지지 않습니다. | `.korean-adhd-always` 파일 위치와 `node --version` 실행 여부를 확인합니다. `CLAUDE_CONFIG_DIR`을 쓴다면 파일을 그 폴더에 둡니다. |
| 회사어투가 적용되지 않습니다. | `.korean-adhd-always` 파일이 함께 있는지 확인합니다. |
| 새 버전의 규칙이 반영되지 않습니다. | 아래 업데이트 명령을 실행하고 새 세션을 엽니다. |
| 규칙을 가끔 지키지 않습니다. | 규칙은 모델에게 주는 지시라서 모델과 요청에 따라 지키는 정도가 다릅니다. "한 줄로 답해" 같은 요청이 있으면 그 요청을 따르기도 합니다. |

Remove-Item "$HOME\.claude\.korean-adhd-always","$HOME\.claude\.korean-adhd-company" -ErrorAction SilentlyContinue

| `skills/korean-adhd/references/korean-rules.md` | 긴 글과 윤문에 쓰는 상세 규칙 |
| `skills/korean-adhd/references/company-tone.md` | 회사어투 옵션 규칙 |
| `hooks/` | 플래그가 있을 때 규칙을 넣는 SessionStart 훅 |
| `tests/run.mjs` | git 외 의존성 없는 테스트 |

Claude Code는 훅 출력을 10,000자까지 그대로 넣고 넘으면 앞 2,000자 미리보기로 바꿉니다. 그래서 테스트가 주입량을 검사합니다. 실제 설치본의 주입량은 기본 약 5,100~5,500자, 회사어투 포함 약 6,200~6,700자였습니다(설치 경로 길이에 따라 다름). 항상 켜기를 쓰면 이만큼 세션마다 컨텍스트에 들어갑니다.

```bash
node tests/run.mjs
claude plugin validate .
```

규칙을 고치면 `.claude-plugin/plugin.json`의 `version`을 올려야 사용자가 업데이트를 받습니다.
